# Onboarding Buddy RAG 🚀

A Retrieval-Augmented Generation (RAG) application built with **Langflow** and **Astra DB** for intelligent interaction with employee onboarding documentation.

The system processes the company's **Employee Onboarding Guide**, stores its content in an Astra DB vector collection, and enables semantic retrieval for downstream question-answering workflows.

---

## 🏗️ Architecture

The project uses **Astra DB Vectorize** to handle embedding generation directly within the database. This approach reduces the need for a separate embedding model component in Langflow and keeps the ingestion and retrieval pipelines simpler.

### Ingestion Flow

```text
PDF Document
     │
     ▼
┌──────────────┐
│   Read File  │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  Split Text  │
│ Chunk: 300   │
│ Overlap: 30  │
└──────┬───────┘
       │
       ▼
┌────────────────────────┐
│       Astra DB         │
│   Vectorize Collection │
└───────────┬────────────┘
            │
            ▼
      Vector Embedding
       generated by
       Astra Vectorize
```

### Main Components

#### 1. Read File

Reads and extracts text from the employee onboarding PDF:

`Panduan Onboarding Karyawan.pdf`

The extracted document content is passed to the text-splitting stage.

#### 2. Split Text

Splits the extracted document into smaller chunks to improve retrieval quality.

Current configuration:

* **Chunk Size:** `300`
* **Chunk Overlap:** `30`

Chunking allows the retrieval system to work with focused pieces of information rather than an entire document at once.

The optimal chunk size may vary depending on the embedding model and the structure of the source documents.

#### 3. Astra DB Vectorize Collection

The processed chunks are stored in an Astra DB collection configured with **Vectorize**.

Instead of generating embeddings through a separate Langflow embedding component, Astra DB automatically generates embeddings from the text submitted through its Vectorize integration. The generated embedding is stored internally in the collection's `$vector` field, while the source text is associated with `$vectorize`.

This allows the same collection to support vector-based semantic search.

# ⚙️ Getting Started

## 1. Create an Astra DB Database

Log in to the [Astra Portal](https://astra.datastax.com/) and create a Serverless database.

Example:

```text
Database:
Knowledge_agent
```

For vector search, create a **vector-enabled collection with a Vectorize integration**.

When creating the collection, configure:

* Collection name
* Embedding provider
* Embedding model
* Vector configuration
* Similarity metric
* Vectorize integration

Astra DB requires vector-related configuration when a collection is created, including vector dimensions and, when applicable, the embedding provider integration.

> **Important:** All embeddings stored in the same collection should use the same embedding model and dimensionality. Mixing incompatible embeddings can produce incorrect vector-search results.

Example collection:

```text
data_onboarding
```

---

## 2. Install and Run Langflow

Install Langflow in your local environment:

```bash
pip install langflow
```

Start Langflow:

```bash
langflow run
```

Then open:

```text
http://localhost:7860
```

---

## 3. Import the Flow

Import the provided **Onboarding Buddy RAG Flow** JSON file into your Langflow workspace.

Configure the Astra DB component with:

* Astra DB Application Token
* Database
* Collection

Example:

```text
Database:
Knowledge_agent

Collection:
data_onboarding
```

### Vectorize Configuration

Because the collection uses Astra DB Vectorize, a separate embedding model component is not required.

Langflow's current documentation confirms that when an Astra DB vector store has a Vectorize integration, the external embedding components can be removed. Astra DB automatically generates embeddings for both ingestion and retrieval.

The ingestion connection should therefore follow this pattern:

```text
Read File
    ↓
Split Text
    ↓
Astra DB
```

No external Gemini/OpenAI embedding node is required for this architecture.

# 📥 Running the Ingestion Pipeline

1. Open the **Knowledge Ingestion** flow.
2. Upload the onboarding PDF through the **Read File** component.
3. Verify that the document is successfully split into chunks.
4. Make sure the **Chunks** output is connected directly to the Astra DB **Ingest Data** input.
5. Verify that the selected collection is the intended Vectorize collection.
6. Run the Astra DB component.

Astra DB will process the text through its Vectorize integration and generate the corresponding embeddings automatically.

# 🔍 Retrieval Architecture

The retrieval flow is separated from the ingestion pipeline.

```text
User Query
    │
    ▼
Astra DB Vectorize Collection
    │
    ▼
Semantic Vector Search
    │
    ▼
Relevant Document Chunks
    │
    ▼
LLM / Response Generation
    │
    ▼
Final Answer
```

The separation between ingestion and retrieval makes the system easier to maintain and allows the knowledge base to be updated independently from the user-facing RAG flow.

# 🛠️ Troubleshooting

## 1. `zip() argument 2 is shorter than argument 1`

### Background

This error was encountered while using an external embedding model through Langflow.

The error indicates that the number of generated embeddings did not match the number of input items expected by the vector-store ingestion process.

Rather than assuming that the PDF itself is corrupted, the issue should be investigated at the embedding/integration layer.

### Solution Used in This Project

The architecture was changed from:

```text
Split Text
    ↓
External Embedding Model
    ↓
Astra DB
```

to:

```text
Split Text
    ↓
Astra DB Vectorize
```

With Vectorize enabled, Astra DB handles embedding generation through its integrated embedding provider instead of relying on a separate Langflow embedding component.

This simplifies the ingestion pipeline and removes the external embedding step that was involved in the original configuration.

---

## 2. `content_field is not configurable for vectorize collections`

This occurs when attempting to manually configure a content field for a collection whose embedding behavior is controlled by its Vectorize integration.

For Vectorize-enabled collections, Astra DB uses the reserved `$vectorize` field to determine the text that should be embedded. The resulting vector is stored in `$vector`.

### Recommended Configuration

Use:

```text
Split Text
    ↓
Astra DB → Ingest Data
```

and allow the Vectorize-enabled collection to manage embedding generation.

If the Langflow component exposes a **Content Field** parameter that is incompatible with the selected Vectorize collection, do not force a custom external embedding configuration. The exact available parameters can depend on the Langflow/Astra DB component version.

---

## 3. Dimension Mismatch

Vector collections have a defined vector dimensionality.

For example:

```text
Collection
Dimension: X

Embedding Model
Dimension: Y
```

If:

```text
X ≠ Y
```

the embeddings are incompatible with the collection.

Astra DB documents that embeddings in a collection should use the same model and dimensionality.

### Recommended Solution

If you switch to a different embedding configuration, create a new collection using the desired embedding provider/model configuration and ingest the documents again.

For example:

```text
Old:
onboarding_docs

New:
onboarding_docs_v2
```

Astra DB's migration guidance for changing embedding models also uses a new collection configured with the desired embedding provider integration.

Do not mix embeddings from incompatible models or dimensions within the same vector collection.


# 🧠 Key Technical Decision

This project intentionally uses **Astra DB Vectorize** instead of managing embeddings externally in Langflow.

The resulting architecture is:

```text
                ┌─────────────────┐
                │  PDF Document   │
                └────────┬────────┘
                         │
                         ▼
                ┌─────────────────┐
                │    Read File    │
                └────────┬────────┘
                         │
                         ▼
                ┌─────────────────┐
                │   Split Text    │
                └────────┬────────┘
                         │
                         ▼
              ┌──────────────────────┐
              │      Astra DB        │
              │   Vectorize Enabled  │
              └──────────┬───────────┘
                         │
                   Auto Embedding
                         │
                         ▼
              ┌──────────────────────┐
              │    Vector Search     │
              └──────────┬───────────┘
                         │
                         ▼
                  Relevant Chunks
                         │
                         ▼
                       LLM
                         │
                         ▼
                    User Answer
```

This design keeps the RAG pipeline modular while delegating embedding generation and vector storage to Astra DB's native Vectorize capabilities.
